# app

The API browser, as a Blazor WebAssembly app. It renders the `oas/openapi.json`
of any API folder in this repository, driven by the root `specs.json`.

This replaces the Stoplight Elements page at the repository root. Elements is a
React viewer with no seam for the things this browser is meant to grow into:
comments backed by GitHub issues, identity, and a view of which Terraform
resources map onto which API operations. Those are application concerns, not
rendering concerns, so the viewer is ours.

## Why it looks like the other sites

The styling is [keel](Browser/wwwroot/css/keel.css), the Claude Design system
already used on the Meridian page at adamcoulteroz.github.io, lifted unchanged:
tokens with a light and dark set, cards, callouts, badges, buttons, and the
tabbed code block. Syntax highlighting is written in C#
([Rendering/Highlighter.cs](Browser/Rendering/Highlighter.cs)) and emits keel's
own token classes, so code colours come from the design system in both themes
rather than from a JavaScript highlighter's palette.

## Layout

Responsive-first: the base stylesheet is the narrow layout and wider
arrangements are added on top. The operation page splits its detail and sample
panes on a **container query**, so the split responds to the width that region
actually has, at any window size and with the nav open or closed. Every grid
track is `minmax(0, …)` so a long code line cannot force a column to overflow.

## Structure

```
app/Browser/
  Model/          a small OpenAPI 3.0 model over JsonElement
  Services/       spec loading and hash routing
  Rendering/      C# syntax highlighting, sample building, inline markdown
  Components/     shell, nav, operation view, recursive schema tree
  wwwroot/css/    keel.css (design system) + app.css (layout)
```

Routing is hash based on purpose: it keeps the deep links this site already
publishes working unchanged (`#/operations/{operationId}`), adds
`#/schemas/{name}`, and needs no rewrite rules on a static host.

Every spec rendered here is generated by this repository in a known shape, so
the model reads the JSON directly rather than carrying a full OpenAPI library
into the browser. Extensions we rely on (`x-notes`, `x-ms-namespace`,
`x-ms-preview`) need no mapping as a result.

## Build

```
dotnet publish app/Browser -c Release -o app/dist
```

The published site expects to be served at `/powerplatform-apis/app/` (see
`base href` in `wwwroot/index.html`), with `specs.json` and the API folders one
level up. Asset fingerprinting is off so the plain `_framework` paths work on a
static host with no mapping layer.

## Status

Viewer reaching parity with Elements: navigation, operations, parameters,
request and response bodies, recursive schemas with cycle handling, deep
linking, samples, notes, and the light and dark themes. Not yet wired up:
GitHub-issue comments, and the Terraform resource-to-API view. The GitHub layer
is intended to sit behind an interface so it can move from unauthenticated
reads on GitHub Pages to real login without a rewrite.
